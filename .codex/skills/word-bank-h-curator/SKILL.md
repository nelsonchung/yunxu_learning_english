# Word Bank H Curator

此 skill 專門處理：

- `assets/word_bank/word_bank_main-h.json`
- `meaning` 不自然、殘留模板、機翻痕跡明顯的條目
- `sentences` 明顯不是正常例句的條目
- 詞性明顯錯誤、且可高信心修正的條目

## Core Rules

- 不使用網路查詢來產生 `meaning` 或 `sentences`
- 只在高信心時修改；不確定的冷僻術語先跳過
- 優先修正常見字、模板污染字、例句明顯失真的條目
- 保留既有其他欄位，例如 `difficultyLevel`、`schoolLevels`、`sourceTags`、`audienceTags`
- 每次只做小批次，速度不是目標，正確率才是
- 單次觸發後，預設要連續處理多批，不要在每批結束後主動停下來等使用者驗證
- 只有遇到停止條件時，才可以結束本次執行

## Detection Hints

優先處理以下污染訊號：

- `How to use`
- `Writers use`
- `still appears in older books and notes`
- `A rare or specialized English term`
- `這句話與`
- 明顯錯誤的中英混雜句
- 把單字當成人、植物、物件亂造句的例句
- 詞性與詞義明顯不符，例如動詞被標成 `noun`

## Workflow

1. 先盤點下一批高信心條目。
2. 只選可穩定修正的小批次，通常 4 到 10 筆。
3. 重寫自然的繁體中文 `meaning`。
4. 重寫 2 句真正可學習的雙語例句。
5. 若詞性明顯錯誤且可高信心判定，一併修正。
6. 用 `apply_patch` 修改檔案。
7. 每批修改後都要驗證 JSON 可解析。
8. 回讀剛修改的條目，確認內容自然且欄位沒壞。
9. 若本批成功且仍有高信心可修條目，直接開始下一批，不要等待使用者回覆。
10. 持續循環，直到命中停止條件。

## Continuation Rule

- 把一次使用此 skill 的請求視為「連續工作請求」，不是「只修一批」。
- 除非使用者明確說停，否則完成一批後應自動接續下一批。
- 不要把「本批已完成」當成自然停止點。
- 若 repo 中仍有大量明顯污染條目，而且目前區段還有高信心可修項目，就應持續執行。

## Stop Conditions

只有在以下情況才停止本次執行：

- 使用者明確要求停止
- 當前區段已沒有高信心可修條目
- 接下來剩下的多數條目屬於低信心冷僻術語
- JSON 驗證失敗，需先回報問題
- 發現資料結構異常，繼續修改風險過高
- 已完成多批，且再繼續很可能進入低信心修正區

## Suggested Run Shape

- 單次觸發時，目標至少完成 2 到 4 批，前提是高信心條目仍持續存在。
- 若使用者說「繼續」，應再次以同樣方式連跑多批，而不是只補一批。
- 若已進入混雜大量冷僻術語的區段，可縮小批次，但仍應先嘗試盤點下一批再決定是否停止。

## Meaning Style

- 以自然、精簡、可學習的繁體中文表達
- 避免照搬英英字典長句
- 能短則短，但不能失真
- 常見格式可用：
  - `X；Y。`
  - `指……`
  - `……的人／事／狀態`

## Sentence Style

- 每筆維持 2 句雙語例句
- 英文句子要自然，不要模板感
- 中文翻譯要順，不直譯到僵硬
- 優先使用一般學習者可理解的情境
- 不要再出現字典說明句、說明頁標題、教學模板句

## Safety Gate

遇到以下情況先跳過：

- 詞非常冷僻，且目前無法高信心確認詞義
- 醫學、礦物、古語、神學術語含義不明
- 看起來可能牽涉專門定義，改錯風險高

## Batch Completion Check

每批完成前必做：

- `JSON.parse(...)` 驗證檔案結構
- 回讀本批條目
- 確認沒有破壞其他欄位
- 驗證通過後，立刻判斷是否直接進入下一批

## Response Pattern

回覆應簡潔，包含：

- 本次總共修了哪些批次與哪些字
- 是否有詞性一併修正
- JSON 是否驗證通過
- 停止原因

## Important Limitation

- 此 skill 可以要求模型在「同一個回合」內連續跑多批。
- 此 skill 不能讓系統在回合結束後自動產生新的使用者訊息或背景常駐執行。
- 因此目標是：每次被觸發時盡量多跑，直到命中停止條件，而不是每批都等使用者確認。
